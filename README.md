# HomeRemote

Небольшое приложение для Windows 10 Pro x64: управление домашним OpenVPN,
RustDesk Portable и отдельными сертификатами устройств. Тёмно-фиолетовая тема,
индикатор состояния в трее, явные команды включения и выключения.

## Поведение

- Крестик скрывает окно, двойной щелчок по значку трея открывает его.
- «Отключить всё и выйти» сначала останавливает домашний VPN и RustDesk.
  При ошибке приложение остаётся открытым.
- Приложение само не включает доступ при запуске.
- Корпоративные процессы OpenVPN не завершаются: проверяются путь EXE,
  абсолютный путь конфигурации, PID и время создания.
- Новое устройство получает отдельный сертификат и `.ovpn`.
  При ошибке экспорта новый сертификат отзывается, CRL обновляется.
  Незаконченный откат блокирует дальнейший выпуск до восстановления.
- Пароль CA вводится для конкретной операции и передаётся через stdin,
  без сохранения в файлы, командную строку или переменные окружения.
- Состояние процессов и порта не гарантирует доступность извне.
- Продление сертификатов в этой версии отсутствует.

## Сборка

Нужны встроенные Windows PowerShell 5.1 и .NET Framework 4.x x64.
Дополнительные программы для сборки не устанавливаются.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Результат: `dist\HomeRemote.exe`. При запуске EXE распаковывает встроенный
runtime в `Application\<id сборки>` рядом с EXE и проверяет SHA-256 компонентов.
Для запуска требуется подтверждение UAC. Исходные `.ps1` рядом с EXE не нужны.

## Рабочие данные

EXE предназначен для уже настроенного сервера. Рядом с ним должны находиться:

```text
EasyRSA/                  # инструменты и существующая PKI
OpenVPN/remote-server.ovpn # домашний серверный конфиг
OpenVPN/ccd/               # существующие назначения адресов
rustdesk-1.5.0-x86_64.exe   # Portable-пакет
HomeRemote-Profiles/       # экспортированные профили, создаётся по необходимости
Logs/                     # журналы, создаётся по необходимости
```

Пути OpenVPN, распакованного RustDesk и параметры клиентского профиля
задаются в `src/Runtime/Remote-Toggle.ps1` и `HomeRemote-Certificates.ps1`.
`-DataRoot` отделяет рабочие данные от встроенного runtime.
После переноса рабочей папки нужно обновить абсолютные пути серверного конфига.
В репозитории **нет** рабочего CA, ключей, сертификатов, клиентских профилей,
реального серверного конфига или сторонних EXE/DLL. `.gitignore` исключает их.

## Проверки

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Smoke.ps1
```

Smoke-прогон запускает EXE в режиме предпросмотра и не управляет настоящими
процессами или сертификатами. Проверяются окно, смена кнопки, трей, отказ
выхода при ошибке остановки и успешный повтор.
Тестовые файлы остаются только в игнорируемой `.test-work` на диске проекта.
Реальная доступность VPN проверяется отдельно с другого устройства.

## Ограничения

Требуются существующие OpenVPN, RustDesk Portable и EasyRSA 3.2.7.
Обновление CRL выполняется вручную; фонового напоминания нет.
Отзыв сертификата не обрывает уже установленный VPN-сеанс немедленно.
Принудительное завершение приложения/сбой питания не гарантирует остановку
удалённого доступа. Полное отсутствие мерцания RustDesk Portable не гарантируется.

## Локальные параметры подключения

Перед созданием устройства скопируйте `HomeRemote.settings.example.json`
рядом с EXE под именем `HomeRemote.settings.json`. Укажите адрес/домен своего
сервера, TCP-порт, имя серверного сертификата и внутренний адрес/порт RustDesk. Эти значения используются
для сборки клиентского `.ovpn`. Локальный файл исключён из Git.
Пример содержит только `vpn.example.invalid`, а не адрес действующего сервера.

Продление CRL обновляет список отзыва, а не сроки сертификатов устройств.
После его истечения новые VPN-подключения будут отклоняться.

Никакие реальные ключи, CA, сертификаты или профили в репозитории не хранятся.
Пароли, рабочие журналы, снимки рабочего стола, внешний адрес домашнего
сервера и тестовые PKI также не публикуются.

Внешний адрес VPN и внутренний адрес RustDesk читаются только из локального JSON. Адрес 192.0.2.1 в примере зарезервирован для документации и не относится к действующей установке.
